Learnings from the review cycle on the MCP integration decision documents (TRI-24, TRI-25, TRI-26). Recorded per `AGENTS.md`: when compiling review feedback, record learnings in `documentation/learnings/` and update relevant rules.

- A missing `db.transaction()` does not justify a compensating write. "The insert failed" and "the insert committed and the response was lost" are indistinguishable to a `neon-http` client, so a best-effort undo can reverse work that actually succeeded. When a multi-table write must be all-or-nothing, express it as one data-modifying CTE and let PostgreSQL roll the whole statement back.
- Hook order in `hooks.server.ts`'s `sequence()` is a security boundary, not wiring. A handler inserted before `authHandle` can answer a request without invoking the downstream `resolve`, so `event.locals.user` is never populated and the handler is serving an unauthenticated request. Anything needing an authenticated user must be sequenced after `authHandle` and must have a test asserting that order, because inverting it is a one-line change with no other symptom.
- A feature flag is enforced where the privileged thing is acquired, not at the outer loop that looks like the entry point. `REVIEWS_ENABLED` is the worked example: the scheduler still runs its drain loop when the flag is false, and the effective gate is `claimNextReviewIntent` returning `null`. An outer-layer check that leaves the inner acquisition ungated reads as coverage and is not.
- A configuration change is not durable while automation redeploys the committed state. `deploy-production.yml` redeploys on every successful push to `main`, so a local or out-of-band flag change is reversed by the next unrelated merge, with nothing announcing the expiry. A durable disable needs the committed state to agree with it.
- Rejecting an attack and accepting one produce different evidence, and conflating them inverts an alert into an outage lever. A refresh-token replay log line records a _rejected_ reuse, so treating one occurrence as a rollback trigger lets any authorized client take the service down by replaying its own token — while the defect that actually matters, silently accepting reuse, may emit nothing at all.
- Not offering a capability is not the same as refusing it. Omitting a scope from client registrations and the consent screen does not make it unobtainable when the client controls the `scope` value it sends. Enforcement belongs at the authorize endpoint: reject anything outside the supported set.
- OAuth scope rules that are correct at authorize can be wrong on refresh. "Granted exactly as requested" is safe where a user is present and approving; carried onto a refresh request it lets a narrowly-granted client widen its own token with nobody watching. A refresh scope must be a subset of the existing grant.
- A reader named for one entity may return more. `getRunInspector` returns agent descriptions and events alongside run rows, so exposing it under a lifecycle-metadata scope would hand over content reserved for a separate, more sensitive scope.
- Function names imply access control they may not implement. `getRepositoryById` performs an unscoped lookup by id; user-facing callers are safe only because they invoke `userCanAccessRepository` separately. Any new consumer on a path where a user or client supplies the repository identifier must add that check itself rather than trusting the name. This does not extend to trusted background consumers — webhook and listener dispatch resolve repositories from already-verified events and have no requesting user — but those still owe their own installation or tenant boundary rather than none.
- Installation-gating controls who can read a value, not who wrote it. Repository and branch names in shared repositories are chosen by administrators who need not be the requesting user, so that metadata is externally authored text and crosses the untrusted-content boundary.
- Consent-screen copy is a security property when it is specified as verbatim display text. Saying "your pull requests" where access is actually scoped by repository understates the grant the user is approving.
- Verify a documented command by running it, including its failure mode. `git clone URL && git checkout SHA` exits 128 because `git clone` does not change the working directory; the check had been performed correctly with `git -C` and written down in a form that cannot pass.
- Cite code by symbol, not line number. Line references drift silently, and a donor revision in this project moved them within a single commit.
