# Settings Matrix

This inventory traces each current user-facing user, repository, and agent setting from the
operator control to persisted state, runtime reader, observable effect, and regression evidence.
It was produced for GitHub issue #202 against `origin/main` at
`c6b323a74b71cccba7a7b5ff42d241019052d6ec`.

## Scope

Included:

- Global review settings on `/settings`.
- Repository review controls on `/repositories`, `/onboarding`, and
  `/repositories/[repositoryId]/settings`.
- Agent list, create, and edit controls on `/agents`, `/agents/new`, and `/agents/[agentId]`.

Excluded:

- Query-string filters on list pages because they are not persisted settings.
- Stop-run and stop-agent controls because they mutate run state, not review configuration.
- `repository_review_settings.check_conclusion_mode` because it is a persisted engine setting, but
  no current user-facing control writes it. The engine path is wired and covered by tests; exposing
  it would be new product surface, not a no-op fix.

## Stored Engine Setting Without Current UI

`repository_review_settings.check_conclusion_mode` is not a current user-facing setting. The schema
default is `advisory`, the only non-default value is `gating`, and the engine path is wired:
`buildPullRequestReviewInput` selects it, `toCheckConclusionMode` normalizes it, and
`buildCompletedCheckRunPatch` turns error-severity findings into a failed Tribunal check run only in
gating mode. Tests in `applications/engine/src/workflows/review-intent-port.test.ts` and
`applications/engine/src/workflows/review-workflow.test.ts` cover both advisory and gating behavior.

Because no UI control writes this field today, it is not a silent no-op. Adding a repository-level
control for it would be a product expansion rather than a defect found by this audit.
